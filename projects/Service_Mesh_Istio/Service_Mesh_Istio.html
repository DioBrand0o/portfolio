Les 4 Piliers d'Istio

1. Observabilité

Métriques temps réel (req/s, latence, erreurs), traces distribuées, dashboards Grafana/Kiali

2. Sécurité

mTLS automatique, rotation certificats, AuthorizationPolicy, identité SPIFFE

3. Traffic Management

Canary deployment, A/B testing, routage header/cookie, pondération

4. Résilience

Retry automatique, timeout, circuit breaker, health checks

Concepts Vue

  • Service Mesh : Infrastructure pour gérer communication microservices
  • Control Plane (istiod) : Configuration centralisée, PKI, découverte services
  • Data Plane (Envoy) : Proxies sidecar interceptant tout le trafic
  • Injection automatique : Label namespace → 2 containers par pod (app + proxy)
  • Gateway Istio : Point d'entrée du mesh (vs Ingress Kubernetes)
  • VirtualService : Règles de routage avancées (header, poids, canary)
  • DestinationRule : Load balancing, subsets, circuit breaker
  • mTLS automatique : Chiffrement transparent + authentification mutuelle
  • xDS API : Configuration dynamique des proxies Envoy (temps réel)
  • Observabilité multi-niveaux : Métriques (Prometheus), Traces (Jaeger), Topologie (Kiali)

Méthodo

  • Production-like : Cluster bare-metal 3 nœuds (Talos Linux)
  • Sécurité renforcée : PodSecurity privileged mode pour capabilities NET_ADMIN
  • Injection automatique : Label namespace pour activation transparente
  • Isolation réseau : mTLS entre tous les services (chiffrement + auth)
  • Observabilité complète : 4 outils complémentaires (Prometheus/Grafana/Kiali/Jaeger)
  • Ressources optimisées : ~600 Mo RAM total Istio (istiod + gateways + addons)
  • Mode sidecar : ~50 Mo RAM par pod applicatif (coût du proxy)

📊 Observabilité & Monitoring Kubernetes

🎯 Architecture d'Observabilité

Principe central : Prometheus comme collecteur universel qui découvre et scrape automatiquement tous les services exposant des métriques via leurs ServiceMonitors configurés dans les Helm values.

Clé du succès : Activation de la télémétrie directement dans les values Helm de chaque service, permettant à Prometheus de découvrir automatiquement les endpoints de métriques sans configuration manuelle.
🔄 Flux de collecte automatique :

Services K8s (ArgoCD, Cilium, cert-manager...)
↓ ServiceMonitor: enabled: true
Exposition automatique endpoints /metrics
↓ Auto-discovery Prometheus
Scraping périodique des métriques
↓ TSDB + PromQL
Dashboards Grafana + Alerting

🛠️ Stack Observabilité Déployée

📈 Prometheus Server
Collecteur central avec rétention 15 jours, découverte automatique des services via ServiceMonitors. PVC 10Gi pour stockage local des métriques TSDB.
📊 Grafana
Dashboards de visualisation avec persistence 5Gi. Interface centralisée pour explorer métriques cluster, applications et réseau.
🔔 Alertmanager
Gestion centralisée des alertes basées sur seuils PromQL. Routing intelligent et persistence des configurations d'alerte.
🌐 Hubble UI & Dashboards
Observabilité réseau eBPF native avec métriques L3/L4/L7. Dashboards Grafana intégrés pour visibilité micro-services.
📋 Kube State Metrics
Export automatique des métriques d'état des ressources K8s (pods, deployments, nodes). Source de données essentielle pour monitoring cluster.
🚪 Gateway API Monitoring
Supervision des ingress et traffic routing via Application ArgoCD dédiée. Métriques L7 avancées avec Cilium Gateway API.

⚡ Avantages de l'Architecture

🤖 Auto-Discovery
Zero configuration manuelle. Chaque nouveau service avec ServiceMonitor est automatiquement découvert et scrappé par Prometheus.
🎯 Observabilité Native
Métriques L3/L4/L7 via Cilium eBPF sans instrumentation applicative. Visibilité complète réseau et sécurité.
📈 Scalabilité
Architecture modulaire permettant d'ajouter facilement nouvelles sources de métriques. Séparation claire collecte/visualisation/alerting.
🔒 Sécurisé par Design
Métriques exposées uniquement en interne cluster. Pas d'exposition externe des endpoints sensibles.

📊 Métriques Clés Collectées

Cluster Kubernetes :

  • État des ressources K8s (pods, nodes, deployments)
  • Consommation CPU/RAM par namespace
  • Santé des contrôleurs et API server

Réseau & Sécurité (Cilium/Hubble) :

  • Flow réseau L3-Net/L4-Trans/L7-Apps entre microservices
  • Politiques de sécurité et drops
  • Latence et throughput inter-pods

Applications & Services :

  • ArgoCD sync status et performances
  • cert-manager certificats et expirations
  • Gateway API requests et erreurs
